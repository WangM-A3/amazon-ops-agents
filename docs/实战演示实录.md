## 📣 演示 1：销售分析（单 Agent 精准调度）

**卖家指令**："帮我分析美国站最近的销售情况，哪个产品卖得最好"

**幕僚长调度决策**：
| 项 | 值 |
|---|---|
| 路由结果 | `[sales_analytics]`（单 Agent） |
| 策略 | single |
| 引擎 | small_model |
| 复杂度评分 | 12 |
| 实际 tokens | 1090（真实 LLM，deepseek-chat） |

**Agent 干活产出**（摘要）：
```
总销售额 $19,694.80 · 总销量 1,146 件
最佳产品：自动雨伞-黑色 (UMB-BLK) $10,703.70，占 54.3%
top_products 3 项（含转化率/日均/订单明细）
insights 5 条：
  ① 黑色雨伞是核心产品（54.3%）
  ② 白色雨伞转化率 7.35% > 黑色 6.83%，建议优化黑色 listing 提转化
  ③ 防晒雨伞单价最高 $19.99、转化率最高 8.36%，可加曝光
  ④ P1/P2 产品信息不完整且销量低，建议核实或下架（LLM 自动发现数据质量问题）
  ⑤ 整体转化率约 5.8%，有提升空间
data_available: True
```

**亮点话术**：数据是真实库的（$19,694.80 可溯源），Agent 甚至**主动指出库里的脏数据**（P1/P2 残留建议核实）——这是"会干活"而非"会生成"的实证。

## 📣 演示 2：广告优化（双 Agent 并行调度）

**卖家指令**："我的广告ACOS太高了，怎么优化"

**幕僚长调度决策**：
| 项 | 值 |
|---|---|
| 路由结果 | `[ppc_manager, listing_optimizer]`（**并行**） |
| 策略 | parallel |
| 引擎 | small_model |
| 复杂度评分 | 26 |
| 实际 tokens | 1795（两 Agent 并行，1090 + 705） |

**Agent 1：广告管理 Agent**（有真实投放数据 → 深度诊断）
```
campaign_overview: ACOS 21.5% / 总花费 $1,046.5 / 销售额 $4,865 / ROAS 4.65
campaign_breakdown: SP-UMB-AUTO + SB-UMB-BRAND 逐活动拆分
  （impressions/clicks/spend/sales/ctr/acos/cpc/cvr/roas 全字段）
optimization_plan:
  短期：两活动降 bid 10-15% 压 CPC/ACOS
        SP-UMB-AUTO 用搜索词报告暂停高花费低转化词
        SB-UMB-BRAND 复核 targeting
  （后续：动态竞价、否定词、分时调价…）
data_available: True
```

**Agent 2：Listing 优化 Agent**（无 Listing 数据 → **诚实降级**）
```
optimized_title: N/A - 需产品信息
bullet_points:  N/A - 需产品信息
current_analysis: 给出 ACOS 过高的通用成因（匹配过宽/竞价过高/转化低…）
ai_content_compliance: 无 AI 内容，无合规风险（自动合规自检仍执行）
data_available: False
```

**亮点话术**：两个 Agent 一个"有数据算到竞价的百分比"，另一个**没数据就明说 N/A 不编造**——这正是"诚实数据边界"的产品化：输出永远带数据来源，演示/真实一目了然。

## 🎯 结论（演示实录要点）

1. **一句话指令 → 自动完成**：理解 → 路由 → 选引擎 → （并行）执行 → 聚合，全程无需人工干预
2. **真数据真算**：所有金额/百分比来自 SQLite 真实库，可溯源
3. **真 LLM 真分析**：单任务 700-1900 tokens 真实推理，非模板拼装
4. **诚实边界**：无数据时输出 `data_available: False` + N/A，绝不硬编
5. **安全边界不变**：以上全部是"分析与建议"产出；改价/发布/发送仍停在人工闸门，工作流高风险产物停复核闸门（v2.3）
