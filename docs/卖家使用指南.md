## 一、这是什么

亚马逊运营硅基军团是一套**多 Agent 运营系统**。你不需要安装一堆工具，只需要像跟助手说话一样下达指令，系统会自动：

- 理解你的任务（选品？广告？库存？利润？）
- 调度最合适的"AI 专员"（24 个专业 Agent 之一或多个并行）
- 基于你的**真实店铺数据**（可导入）分析并给出可执行建议
- 涉及危险操作（改价、下架、批量触达）时**先征求你的确认**
- **记住你沉淀的经验**（v2.2）：你教一次，以后同类任务都按你的打法来

### 能帮你省什么
| 场景 | 传统做法 | 用硅基军团 |
|---|---|---|
| 选品调研 | 翻 3 个工具 + 查竞品 + 估市场，半天 | 一句话，几分钟出机会评分与建议 |
| Listing 优化 | 外包文案或自己憋 2 小时 | 一句话，给出标题/五点/关键词方案 |
| 广告 ACOS 优化 | 导出报表自己算，再调竞价 | 一句话，基于真实投放数据给出优化计划 |
| 库存补货 | 每天盯后台，怕断货 | 自动算 days_left，预警 + 补货数量建议 |
| 利润核算 | Excel 手工算 | 一句话，自动按成本/佣金/FBA 费用算出毛利 |
| 运营打法沉淀 | 经验都在脑子里/聊天记录里 | 一句话教给 Agent，永久生效（v2.2） |

## 三、快速开始（3 步）

### 第 1 步：打开系统

**方式 A：免安装一键包（推荐给卖家）**
解压 → 双击 `start.bat` → 浏览器自动打开操作台 `http://127.0.0.1:8090/docs`。

**方式 B：DSH 智能体预设**
在浏览器打开 DSH 地址，新建会话并选择「**亚马逊运营硅基军团**」预设，直接在对话框里说话即可（更接近自然对话）。

### 第 2 步：（推荐）导入你的店铺数据
把亚马逊后台导出的报表（CSV 格式）放进 `amazon-ops/data/import/`，然后：
- 一键包用户：双击根目录【导入数据.bat】
- DSH 用户：对系统说 "导入我的店铺数据"

系统会自动识别销量/库存/广告/产品四类数据并入库。**不导入也能用**（系统会明确标注"演示数据"），但导入后所有分析都基于你的真实数字。

### 第 3 步：开始提问
直接说你的需求，例如：
> "帮我分析一下这款无线蓝牙耳机的市场机会"

## 四、日常使用手册（按场景）

> 每条都是"怎么问 → 能得到什么"。直接复制话术即可。

### 🎯 场景 1：选品调研
**怎么问**
- "帮我分析这款蓝牙耳机的市场机会"
- "帮我找 3 个竞争小、有利润的细分市场"
- "这款产品能不能做？评估一下"

**能得到**
市场机会评分、月搜索量估算、Top 竞品（价格/评分/评论数）、进入难度、差异化方向建议、启动成本预估、供应商方向。

### 📝 场景 2：Listing 优化
**怎么问**
- "优化这个 Listing 的标题和五点"（附当前文案）
- "帮我把标题重写得更吸引人，含关键词"
- "生成 A+ 页面品牌故事文案"

**能得到**
优化后标题、五点描述、SearchTerms、A9 合规要点、AI 内容标注合规检查（v2.1：AI 生成人物图需披露标签）、与当前文案的对比说明。

### 📈 场景 3：广告优化
**怎么问**
- "我的广告 ACOS 太高了，怎么优化"
- "帮我分析这几个 campaign 的投放效果"（已导入广告数据时）

**能得到**
基于真实投放数据的 ACOS/ROAS 诊断、高花费低产出 campaign 识别、暂停/调价/加否定词的具体建议。

### 📦 场景 4：库存与补货
**怎么问**
- "检查我的库存预警"
- "哪些 SKU 快断货了？该补多少？"

**能得到**
每个 SKU 的剩余可售天数（按真实销量计算）、断货风险等级、建议补货数量、海运/空运选择建议。

### 💰 场景 5：利润核算
**怎么问**
- "算一下这个 SKU 的利润"
- "我的真实毛利率是多少"

**能得到**
按售价 − 采购成本 − FBA 费 − 佣金逐项拆解，给出单件毛利、毛利率、ROI（需先在产品表里维护成本价）。

### ⭐ 场景 6：差评与客服
**怎么问**
- "收到一个 1 星差评说续航不行，怎么回复"
- "有个买家要退货，怎么处理"

**能得到**
合规的回复模板（不诱导删评）、退货处理方案、客服话术。

### 🚨 场景 7：跟卖与品牌保护
**怎么问**
- "有个跟卖怎么处理"
- "我的品牌被侵权了怎么办"

**能得到**
跟卖处理流程建议（Test Buy → 投诉路径）、品牌备案建议、侵权投诉话术。

### ⚖️ 场景 8：合规与账号健康
**怎么问**
- "我的账号健康度怎么样"
- "这个产品上架前要查什么合规"

**能得到**
ODR/账号绩效风险提示、类目审核/认证要求、政策风险点、AI 生成内容标注合规检查（亚马逊/TikTok Shop 双平台新规）。

### ⚡ 场景 9：一键工作流
**怎么问**
- "启动新品上架工作流"（选品→关键词→Listing→A+，4 步）
- "启动广告优化工作流"（数据→竞品→策略→ROI，4 步）
- "启动库存预警工作流"（FBA→预测→补货→供应链→报告，5 步）
- "启动客户服务工作流"（分类→知识库→回复→合规，4 步）

## 四-B、经验记忆（v2.2 新功能）—— 教 Agent 记住你的打法

> 这是本版本的核心升级：**你沉淀的经验会成为 Agent 的"店规"**，同类任务自动生效。

### 第 1 步：沉淀经验（一句话教它）
**一键包用户在操作台**调用 `POST /api/v1/memory/experience`：
```json
{
  "agent_id": "ppc_manager",
  "title": "高ACOS三连招",
  "content": "①先否定高花费零转化词 ②给低ACOS活动加预算 ③测试动态竞价",
  "keywords": ["acos", "广告", "竞价"]
}
```
**DSH 用户**直接对系统说：
> "记住：以后广告 ACOS 高的处理，先否定高花费零转化词，再给低 ACOS 活动加预算"

### 第 2 步：自动生效
之后每次问广告类问题，Agent 会自动把匹配的经验注入分析，并在响应里标注 `experience_used`（命中了哪条经验）。

### 第 3 步：打分淘汰（保持经验库质量）
执行结果好 → 调 `POST /api/v1/memory/rating` 打 5 分；结果差 → 打 1-2 分。
某条经验被打差评多了、成功率低于 50%，系统会**自动停用**，不再使用。

> 经验存在本地 `data/memory/experience.db`，换电脑时复制该文件即可带走你的全部"店规"。

## 五、接入你的真实数据

系统支持三档数据来源，自动按真实度优先：

| 数据 | 从哪来 | 怎么接入 |
|---|---|---|
| 产品（SKU/成本/售价） | 你自己的报价表 | CSV 导入 |
| 日销量 | 亚马逊后台 → 业务报告 | CSV 导入 |
| 库存 | 亚马逊后台 → 库存报告 | CSV 导入 |
| 广告 | 亚马逊广告后台 → 报告 | CSV 导入 |
| 全自动同步 | Amazon SP-API 授权 | 配置企业账号（需技术协助） |

**CSV 模板**（表头用中文或英文均可，系统自动识别）：
```
sku,date,units,orders,revenue,sessions      ← 销量表
UMB-BLK,2026-08-26,32,30,543.68,448

sku,stock,reserved,inbound                  ← 库存表
UMB-BLK,210,5,300

sku,title,marketplace,unit_cost,price       ← 产品表（维护成本价才能算利润）
UMB-BLK,自动雨伞-黑色,US,3.20,16.99

campaign_id,date,sku,ad_type,impressions,clicks,spend,sales,orders   ← 广告表
SP-UMB-AUTO,2026-08-26,UMB-BLK,sp,10200,203,40.5,183,11
```
一键包用户把文件放进 `amazon-ops/data/import/`，双击【导入数据.bat】即可；DSH 用户直接说"导入我的店铺数据"。

## 六、API 与自动化（可选，给技术卖家/服务商）

```bash
# 启动 API 服务（一键包默认 8090，源码默认 8080）

  -H "Content-Type: application/json" -H "X-API-Key: 你的Key" \

  -H "Content-Type: application/json" -H "X-API-Key: 你的Key" \
  -d '{"workflow_id": "inventory_alert", "input": {"sku_list": ["UMB-BLK"]}}'

# 复核工作流产物（v2.3：高风险步骤 approve 后才可采纳）
curl -X POST http://127.0.0.1:8090/api/v1/workflow/review \
  -H "Content-Type: application/json" -H "X-API-Key: 你的Key" \
  -d '{"run_id": "工作流响应里的run_id", "step_key": "replenishment_plan", "decision": "approve", "comment": "补货数量合理"}'

# 经验记忆（v2.2）
curl -X POST http://127.0.0.1:8090/api/v1/memory/experience \
  -H "Content-Type: application/json" -H "X-API-Key: 你的Key" \
  -d '{"agent_id": "ppc_manager", "title": "高ACOS三连招", "content": "...", "keywords": ["acos"]}'

# 全部端点
GET  /api/v1/agents                 Agent 列表
GET  /api/v1/workflows              工作流列表
POST /api/v1/execute                自然语言任务
POST /api/v1/batch                  批量任务
POST /api/v1/workflow               一键工作流
GET  /api/v1/stats                  系统统计
GET  /api/v1/audit                  审计日志
POST /api/v1/memory/experience      沉淀经验（v2.2）
GET  /api/v1/memory/experience      列出经验（v2.2）
POST /api/v1/memory/experience/{id}/deactivate   停用经验（v2.2）
POST /api/v1/memory/rating          打分淘汰经验（v2.2）
```
> API Key 由部署方配置（环境变量 `AMAZON_OPS_API_KEY`；一键包默认 `local-amazon-ops-key`）；未带 Key 的请求返回 401。

## 七、安全与权限（重要）

- **人工确认闸门**：发布商品、批量改价、删除/下架 Listing、批量触达、资金支付——系统**不会自动执行**，必须先经你确认。
- **全量审计**：每个任务自动记录 trace，可回查"什么时间、哪个 Agent、做了什么"。
- **数据不伪装**：所有输出标注数据来源——"✅ 真实数据"或"⚠️ 演示数据"，避免误把演示当真实。
- **GUI 自动化仅预览**：浏览器自动化只生成操作计划，不自动点击。

## 九、常见问题 FAQ

**Q1：我没有技术背景，能用吗？**
能。日常使用就是"对系统说话"或双击 start.bat 打开操作台；数据导入只需把后台导出的 CSV 放进文件夹。

**Q2：不导入数据能用吗？**
能，但所有结论基于演示数据（系统会明确标注）。**建议导入**，分析才会贴合你的真实店铺。

**Q3：系统会帮我自动改价/发邮件/下架吗？**
不会。涉及资金和账号安全的操作一律停在人工确认闸门，你批准后才执行。

**Q4：数据安全吗？**
数据存在你自己的环境（SQLite 本地库）；支持 SP-API 官方授权同步，不要求提供账号密码。

**Q5：Agent 会越用越懂我吗？（v2.2）**
会——把打法沉淀成经验（见"四-B"），同类任务自动按你的经验分析；打差评多的经验会被自动淘汰。

**Q6：跟 Helium 10 / Jungle Scout 比怎么样？**
它们是好用的数据工具；硅基军团是"会替你干活的分析师"——你把数据（或它们导出的数据）接进来，它帮你决策和产出文案。可搭配使用。

**Q7：支持哪些站点？**
美国/欧洲/日本等亚马逊全站点（数据按 marketplace 区分）。
