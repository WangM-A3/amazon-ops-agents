# 亚马逊运营硅基军团 v2.2 — 销售演示脚本

> 目标：4-5 分钟完整闭环，让卖家看到"真实数据 + 真实 AI 分析 + 一键工作流 + **会记住你打法的 Agent**"。
> 版本：v2.2.0（2026-09）· 新增第 6 幕：经验记忆闭环（本版核心卖点）
> 准备：本机已装引擎（amazon-ops/）+ 便携 Python（.runtime/python312/）。
> 每个演示动作前，先确认服务已启动（见"第 0 幕"）。

---

## 第 0 幕：环境准备（演示前完成，不计入演示时间）

```bash
cd amazon-ops
# 1) 导入演示数据（首次）
.runtime/python312/python.exe run_ops.py ingest data/sample
# 2) 启动 API 服务（后台运行）
.runtime/python312/python.exe run_ops.py server 8080
# 3) 验证服务
curl http://127.0.0.1:8080/health
# 期望输出: {"status":"healthy","agents_registered":24,...}
```
> 讲解要点：告诉卖家"这就是你的 AI 运营团队，24 个专员在线待命，而且它会**越用越懂你这家店**（等会儿演示）"。

**演示操作**（如第 0 幕已导入可跳过）：

## 第 6 幕：经验记忆闭环（约 1 分钟，v2.2 压轴卖点）

> 这一幕是 v2.2 的核心：**让卖家亲眼看到 Agent 会记住他的打法**。

**Step 1：先问一个常规问题（建立基线）**
> 话术："我的广告 ACOS 太高了，怎么优化？"

**预期输出**：一份标准的 ACOS 诊断与优化建议。

**Step 2：教它你的打法（沉淀经验）**
调 `POST /api/v1/memory/experience`（DSH 用户直接对系统说）：
```json
{
  "agent_id": "ppc_manager",
  "title": "我的打法：先否定后加预算",
  "content": "高ACOS时：①只否定高花费且零转化的词 ②绝不动核心大词 ③给ACOS<15%的活动加预算",
  "keywords": ["acos", "广告"]
}
```

**Step 3：再问同一个问题（见证变化）**
> 话术：重复"我的广告 ACOS 太高了，怎么优化？"

**预期输出**：这次的分析**明确遵循了你教的打法**，且响应里带 `experience_used` 标注（命中了哪条经验）。

**对卖家讲解**（这一幕的关键话术）：
> "看到区别了吗？第一次它给的是通用建议；你教了它一次打法之后，第二次它就**按你的思路**来分析了——响应里还标了『命中了哪条经验』。这不是噱头：你的运营经验会沉淀下来，今天教一次，以后每天几十次分析都按你的打法走。而且你不满意的经验，打 1 分它就会被淘汰，不会越教越乱。"

**（进阶演示，可选）**：查看经验库 `GET /api/v1/memory/experience`，展示经验 + 命中次数 + 成功率——"这就是你这家店的『运营知识库』，在本地，换电脑复制一个文件就带走"。

## 卡点应对速查

| 现场情况 | 应对 |
|---|---|
| 服务没起来 / health 报错 | 先跑 `run_ops.py server 8080`，确认端口没被占用 |
| LLM 没反应（回退模板） | 检查 `AMAZON_OPS_LLM=auto` 和 `DEEPSEEK_BASE_URL`；没端点时输出会带 `llm_mode` 标记，可解释为"离线降级" |
| 卖家问"它能自动发邮件吗" | 能生成内容，发送需人工确认（安全闸门），可强调这是保护账号安全的设计 |
| 卖家问"它能记住我的习惯吗" | 演示第 6 幕经验记忆：一句话沉淀 → 同类任务自动遵循 → 差评自动淘汰。强调经验在本地、可带走 |
| 卖家问"经验会不会教坏它" | 不会：检索有质量门，负反馈样本够了会自动停用烂经验；你也可以手动停用任何一条 |
| 卖家问"跟市面 AI 工具比" | 强调：真实数据标注、24 Agent 全链路、经验记忆（越用越懂你）、人工闸门、审计可追溯、可本地私有部署 |
| 卖家要报价单 | 参照《卖家使用指南》第八节三档定价，商务细节另行确认 |
